# Doctor Hunt Project Coding Rules & Standards

This document establishes the strict architectural, localization, styling, asset management, and code structure rules for the Doctor Hunt project. All AI agents and developers modifying this codebase MUST strictly follow these rules.

---

## 1. Absolute Directives (NO Hardcoding)

1. **NO Hardcoded UI Text Strings**:
   - ALL user-facing text strings MUST be defined in `assets/translations/en.json` (or `strings.json`) as a flat key-value object.
   - Text strings MUST be referenced using `tr.keyName` generated by `slang`.
   - Direct string literals in `Text(...)`, `hintText: ...`, `title: ...`, or button labels are STRICTLY PROHIBITED.

2. **NO Hardcoded Colors**:
   - ALL colors MUST be defined as static constants in `AppColors` (`lib/apps/core/themes/app_colors.dart`).
   - Use design system semantics (`AppColors.primary`, `AppColors.textMain`, `AppColors.textSub`, `AppColors.textBorders`, `AppColors.white`, etc.).
   - Hex values like `Color(0xFF0FCE92)` inside UI widgets are STRICTLY PROHIBITED.

3. **NO Hardcoded Text Styles**:
   - ALL text styles MUST use the generated `style_atoms` extensions on `BuildContext` (e.g., `context.bold24TextMain`, `context.medium14TextSub`, `context.bold16White`).
   - Instantiating explicit `TextStyle(...)` objects in UI widgets is STRICTLY PROHIBITED.

4. **SizedBox Spacing Syntax**:
   - Use number extension getters `16.h` and `16.w` from `custom_sized_box.dart` for all spacing in layout columns and rows (e.g., `16.h`, `8.w`, `24.h`).

---

## 2. Directory & Architecture Standards

1. **Screen Directory Naming**:
   - Folders containing screen widgets MUST be named `screens` (e.g., `lib/apps/features/auth/presentation/screens/`).
   - The directory name `pages` is strictly deprecated and MUST NOT be used.

2. **Clean Widget Structure (No Unnecessary `_build` Methods)**:
   - Keep screen `build()` methods clean, direct, and inline.
   - Do NOT create trivial `_build...` helper methods for simple inline layout rows/columns.
   - Extract widgets into separate standalone widget classes in `widgets/` ONLY when a component is genuinely reusable across screens or genuinely complex (e.g., `AuthBackground`, `SocialButtonsRow`, `CustomTextField`, `CustomMainButton`).

---

## 3. Strongly-Typed Navigation (`go_router_builder`)

1. All routes MUST be declared in `lib/apps/core/router/app_router.dart` using `@TypedGoRoute`.
2. Code generation via `dart run build_runner build` creates `app_router.g.dart`.
3. Navigations MUST use typed route instances, e.g.:
   ```dart
   const LoginRoute().go(context);
   const SignUpRoute().go(context);
   ```

---

## 4. Code Generation Workflows

When updating assets, colors, router, or translations, run the following commands:
- **Asset Code Generation**: `dart run generate_styles.dart` to refresh `style_atoms.dart`.
- **Localization**: `dart run slang` to regenerate `translations.g.dart`.
- **Typed Router**: `dart run build_runner build --delete-conflicting-outputs` to regenerate `app_router.g.dart`.
